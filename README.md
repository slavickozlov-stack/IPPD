# ИППД Контроль (MVP)

Настольное приложение для кейса Ростовской АЭС: проверяет **актуальность УММ**, на которые ссылается индивидуальная программа подготовки на должность (ИППД), на выбранную дату и выполняет **формализуемый нормоконтроль ИППД**. Результат — отчёт для специалиста: у каждого замечания есть место в документе, фактическое значение, требование и основание.

Документы обрабатываются локально, без сетевых запросов; исходные файлы только читаются.

## Команды

Нужен Node.js 20+ (проверено на 22.23).

```bash
npm install
```

```bash
npm run dev
```

Запуск в режиме разработки (Electron и Vite с горячей перезагрузкой).

```bash
npm run build && npm start
```

Сборка и запуск собранного приложения.

```bash
npm test
```

Модульные тесты (vitest): чтение УММ из DOCX, PDF и сканов, сроки действия, пересмотр, отсутствующие даты, конфликты редакций и источников, шаблоны, пустые ячейки, неполный разбор, демо-комплект.

```bash
npm run e2e
```

Сквозной прогон в настоящем Electron (Playwright): демо-комплект и папка образцов УММ → сверка с ручной правкой → проверка → фильтр → экспорт HTML → добавление новой редакции УММ с немедленной перепроверкой. Скриншоты и отчёт попадают в `e2e/output/`.

```bash
npm run typecheck
```

```bash
npm run dist
```

Упаковка дистрибутива через electron-builder в `dist/` (в MVP не проверялась).

Вспомогательные команды: `npm run demo:generate` пересоздаёт синтетический комплект, `npm run demo:pdf` — PDF-образцы форм УММ, `npm run schema` обновляет `schemas/profile.schema.json`, `npm run cli -- --demo --out отчёт.html` запускает проверку без интерфейса.

## Демонстрация

1. `npm run build && npm start`.
2. **Загрузка файлов** → «Загрузить демо-комплект». Подставятся синтетическая ИППД, 10 УММ в DOCX, «скан» PDF, реестр XLSX, дата 01.12.2026 и профиль «ДЕМО».
3. **Извлечь данные** → **Сверка**: видно, что разбор полный, 10 ссылок, ключи сопоставления, место каждой ссылки (таблица/строка/графа) и реквизиты УММ с происхождением (наведите на значение). У PDF реквизиты неизвестны: «изменить» → статус «действующий», окончание 31.12.2027, обоснование → «Сохранить». Отметьте «Извлечённые данные сверены».
4. **Запуск проверки**: таблица показывает, какие проверки настроены в профиле.
5. **Отчёт**: итог «Есть замечания». Ожидаемые статусы:

| Тема | УММ | Статус |
|---|---|---|
| 1.1, 2.4 | 0101.2024 (в 2.4 записан с латинской K) | действует |
| 1.3 | 0103.2022 → замена 0207.2025 | заменён, показана замена и её статус |
| 1.4 | 0102.2021 | срок действия истёк |
| 1.5 | ИОТ.99.01 изм.3 (скан) | требуется уточнение (после ручного ввода — действует) |
| 2.1 | 0104.2021 | просрочен пересмотр (документ действует) |
| 2.2 | 0105.2023, две редакции | действует: выбрана изм. 2 по демо-правилу |
| 2.3 | 0109.2022 | не найден в загруженных материалах |
| 2.5 | 0106.2024: файл и реестр расходятся | срок действия истёк: применён приоритет реквизитов УММ над реестром |
| 2.6 | 0108.2024 (только в реестре) | отменён |
| 2.7 | 0110.2023, загружен новый УММ той же темы 0215.2026 | заменён: новая редакция — новый номер, ссылку нужно пересмотреть |

Нормоконтроль — 9 нарушений: нет листа регистрации изменений (NC-07), пустая графа «Учебные материалы» (NC-30), пустой ответственный за стажировку (NC-32), пустые календарные сроки (NC-33), дата `1.10.2026` (NC-40), нумерация 1.1 → 1.3 (NC-50), латиница в обозначении (NC-60), «Сп» с ПАЗ (NC-61), ссылка на несуществующую запись [9] и неиспользуемая [8] (NC-62). Ещё 5 проверок — ручные (оформление страниц, подписи, соответствие ППД и др.).

6. «Добавить УММ и перепроверить…» → выберите `demo/дополнительно/УММ I.К1.Т13.УМСИ.ДЕМО.0301.2026 (новая редакция).docx`. Проверка запускается сразу: темы 1.1 и 2.4 получают статус «заменён» со ссылкой на 0301.2026. Итог становится «Проверка неполная», пока реквизиты нового файла не сверены на шаге «Сверка».
7. Фильтр по статусам и итогам, вкладки «Актуальность УММ» / «Нормоконтроль» / «Файлы и профиль», «Экспорт HTML…» — самодостаточный файл с тем же содержимым и фильтром.

## Новые редакции УММ

Новая редакция УММ выпускается **под новым номером** (ответ специалиста УТП, 10.11.2026). Поэтому УММ считается новой редакцией ссылочного, если у него совпадают уровень, курс, тема, вид и подразделение, а год более поздний. Пример: `I.К1.Т13.УМСИ.ООП.3591.2024` → `I.К1.Т13.УМСИ.ООП.4801.2026`. Настройка `actuality.newerEditionPolicy`:

- `replaced` — если новый УММ действует на дату проверки, ссылка на старый получает статус «заменён» с указанием нового; если новый ещё не действует — «требуется уточнение»;
- `clarify` — всегда «требуется уточнение»;
- не настроено — статус не меняется, в проверках ссылки остаётся подсказка о новом УММ.

УММ с тем же годом, но другим номером новой редакцией не считаются: в реальной ИППД встречаются два действующих УММ одной темы одного года (`III.К18.Т1.УМСИ.ОППТОиР.3303.2023` и `…3273.2023`).

## Поддержанные форматы

| Роль | Формат | Что извлекается |
|---|---|---|
| ИППД | DOCX по форме прил. В П.00.10 (проверено на трёх реальных вариантах: УТП, ЦТАИ, ЕОСДО) | рег. номер, ФИО, должность; таблицы план-графика, теоретической/практической подготовки, стажировки; графа «Учебные материалы» / «Номер УММ»; библиография |
| ИППД | иная форма, PDF, DOC | «неподдерживаемый шаблон» / ошибка формата → ручной разбор, итог «Проверка неполная» |
| УММ | DOCX (в т. ч. в оформлении АСУТД: титульный лист, предисловие, колонтитулы) | обозначение, наименование, изменение, статус и дата статуса (штамп АСУТД), даты введения/окончания/пересмотра/утверждения, «Взамен», «Заменён на» |
| УММ | PDF с текстовым слоем (выгрузка из АСУТД) | то же, с номером страницы в месте извлечения |
| УММ | PDF-скан со штампом АСУТД | статус и дата статуса из штампа; обозначение и изменение — по имени файла (помечены «выведено»); остальное — ручной ввод |
| УММ | PDF-скан без текста | только имя файла; реквизиты — ручной ввод |
| УММ | DOC, ODT, RTF | понятная ошибка «сохраните как DOCX или PDF» |
| Реестр | XLSX (первый лист) или CSV; строка заголовков ищется по графе «Обозначение» | те же поля, сопоставление столбцов по синонимам |

DOC, ODT и RTF не читаются. Формулы и макросы не исполняются: читаются только сохранённые значения и XML текста. PDF читается через pdf.js без отрисовки страниц, без подключения шрифтов и без исполнения скриптов документа.

## Подключение реальных УММ

Образцов реальных УММ пока нет. Чтение подготовлено по оформлению документов АСУТД, которые есть в папке «Доки для программы»: П.00.10, ППД.27.ЦТАИ.80, ПР.ИД.27.09 (PDF с текстом) и ИД.27.09, ИОТ.27.26, П.00.41 (сканы со штампом). На них проверено:
- статус и дата статуса берутся из штампа «АСУТД-2. Действующий. № … от … Печать …» (он есть даже у сканов);
- номер изменения — наибольший «зам N» / «нов N» в колонтитулах (31 для П.00.10, 8 для ППД);
- обозначение — из отдельной строки титульного листа или колонтитула;
- «Дата введения в действие» и «Дата окончания действия» с прочерками отмечаются как «есть, но не заполнено»;
- «ВЗАМЕН …» в предисловии со ссылкой на то же обозначение считается предыдущим изменением, а не другим УММ.

Когда появятся файлы:

1. Прогоните диагностику:
   ```bash
   npm run cli -- --probe-umm путь/к/УММ/*.docx путь/к/УММ/*.pdf
   ```
   Для каждого файла выводятся форма (DOCX, PDF с текстом, скан со штампом, скан), найденные реквизиты с местом извлечения и строки, похожие на реквизиты, которые не сопоставлены ни с одним полем. То же видно в приложении на шаге «Сверка», в колонке «Распознано».
2. Несопоставленные подписи добавьте синонимами в `templates/umm-card.template.json` (`labels`, `titleTypeWords`, `statusWords`, формат штампа `asutdStamp`). Код менять не нужно. Без двоеточия распознаются только датированные реквизиты и «Взамен» — это защита от заголовков таблиц.
3. Если реальные УММ можно включать в тесты (без персональных данных), положите обезличенные копии в отдельную папку и добавьте ожидания по образцу `tests/umm.test.ts`.

В приложении УММ можно загрузить целой папкой («Папка…»): подпапки до 5 уровней, не более 500 файлов, скрытые и временные файлы Word `~$…` пропускаются.

Синтетические образцы форм: `demo/образцы форм УММ/` (DOCX и PDF в оформлении АСУТД, скан со штампом «Заменён»).

## Как устроено

```
src/core/      извлечение и проверка, без зависимостей от Electron
  docx.ts, pdf.ts, tabular.ts    чтение DOCX, текстового слоя PDF, XLSX, CSV
  ippdExtract.ts, ummExtract.ts  извлечение по JSON-шаблонам из templates/
  designation.ts                 нормализация обозначений (латиница/кириллица, пробелы, ведущие нули сохраняются)
  actuality.ts                   сопоставление и статусы УММ на дату
  rules/engine.ts                движок нормоконтроля
  profile.ts                     JSON-схема профиля и типы проверок
  pipeline.ts, reportHtml.ts     сквозной сценарий и экспорт
src/main/      окна, диалоги, IPC с проверкой входных данных (zod), блокировка сети
src/preload/   ограниченный API window.ippd (10 вызовов)
src/renderer/  React-интерфейс, 4 шага
profiles/ templates/ demo/ schemas/ tests/ e2e/ docs/
```

Безопасность: `contextIsolation`, `sandbox`, без Node.js в renderer, CSP, запрет навигации, новых окон и webview, отмена всех сетевых запросов, IPC принимается только со страницы приложения. Renderer не передаёт пути: файлы выбираются системным диалогом в main и далее адресуются идентификаторами.

## Профили правил

| Профиль | Режим | Назначение |
|---|---|---|
| `demo` | demo | 28 автоматических и 5 ручных правил, настройки актуальности — всё помечено ДЕМО. Только для синтетики. |
| `roaes-p0010-draft` | work | те же правила с пунктами П.00.10 изм.31, но `approval: "draft"`: в отчёте они идут как «требуется ручная проверка» с текстом требования и источником. Подтверждены ответом специалиста от 10.11.2026 и применяются: приоритет реквизитов УММ над реестром и немедленный пересмотр при загрузке нового УММ той же темы |
| `work-empty` | work | пустой: отчёт показывает, что ни одна проверка не настроена |

В рабочем режиме применяются только правила и настройки с `"approval": "confirmed"`. Итог «Замечаний нет» доступен, только если разбор полный, данные сверены, все проверки настроены и выполнены, а ручных проверок не осталось.

### Как подключить реальные правила

1. Скопируйте `profiles/roaes-p0010-draft.profile.json`, задайте новый `id`, `name`, `version`.
2. Для каждого правила, которое специалист подтвердил, замените `"approval": "draft"` на `"confirmed"`; при необходимости уточните `requirement`, `source`, `severity` и параметры `check`.
3. Заполните `actuality` (см. [docs/QUESTIONS.md](docs/QUESTIONS.md)), например:
   ```json
   "validToInclusive": { "value": true, "approval": "confirmed", "source": { "document": "П.xx.xx", "clause": "п. N" } }
   ```
4. Новые требования поддержанных типов добавляются в JSON без изменения кода. Типы: `paragraph_present`, `field_format`, `table_present`, `table_structure`, `cells_filled`, `dates_format`, `numbering`, `designation_format`, `form_material_match`, `bibliography_crossref`, `manual`. Схема — `schemas/profile.schema.json`.
5. В приложении: «Импорт профиля…» — файл проверяется по схеме и копируется в папку данных пользователя. Версия и SHA-256 профиля попадают в отчёт.

### Как подключить новый шаблон документа

- **ИППД**: скопируйте `templates/ippd-roaes-p0010.template.json`, задайте `id`, шаблоны распознавания (`detect.patterns`), заголовки граф таблиц (`headerAll`, варианты через `|`) и синонимы столбцов. В правилах профиля укажите `template` с этим `id`.
- **УММ**: подписи реквизитов, формат штампа АСУТД и слова статусов — `templates/umm-card.template.json`.
- **Реестр**: синонимы столбцов — `templates/registry-v0.template.json`.

Шаблоны читаются при запуске; правка кода не нужна. Источники подтверждённых полей и правил: [docs/SOURCES.md](docs/SOURCES.md).

## Ограничения MVP

- Реальных УММ и выгрузки реестра в исходных материалах нет — их форматы синтетические и требуют подтверждения.
- Номера страниц DOCX не определяются: место указывается разделом, таблицей, строкой, графой или абзацем.
- Оформление страницы, подписи и их подлинность, соответствие ИППД программе ППД, комплектность пакета — только ручная проверка.
- Тесты, e2e и CLI проверены на macOS (arm64); сборка дистрибутива (`npm run dist`) не проверялась.
